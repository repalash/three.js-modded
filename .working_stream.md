# IJ-530: Rhino3dmLoader skips the document strings when loadUserDataStrings is false

Ticket: https://ijewel3d.youtrack.cloud/issue/IJ-530

## For the person
- Draft. The 3DM worker read every document string, even when the app discards them. rhino3dm reads them in O(n²) time, so a 36 MB customer file with 31,927 strings took about 70 s in Playground.
- `Rhino3dmLoader.loadUserDataStrings` (default `true`, today's behaviour) is sent to the worker with the decode message; with `false` the worker skips the strings loop.
- To take effect in our products, webgi `Rhino3dmLoader2.decodeObjects` must set `this.loadUserDataStrings = Rhino3dmLoader2.LoadUserDataStrings` (a separate webgi change), then a webgi release and version bumps.
- Next: Palash reviews, publishes three-modded, webgi takes the new version.

## Detail
- `examples/jsm/loaders/3DMLoader.js`: property in the constructor, sent in `decodeObjects()`'s `postMessage`; the worker passes `message.loadUserDataStrings !== false` to its `decodeObjects()`, which gates the `doc.strings()` loop. A message without the flag keeps the old behaviour.
- `CHANGELOG.md`: Unreleased entry.
- Tested in Chrome with a standalone page (three-modded build + this loader, rhino3dm 8.0.1 from jsDelivr) on the customer file; numbers in the PR body.
